## O -> P 연결 (40e0cb2, `src/ctrec/followup/service.py`만)

1. **세 번째 선택 경로 제거**: O는 `FullDCVCPolicy`를 직접 만들어 `select`·`apply_outcome`을 불렀다. 이제 요청 기록으로 `engine.loop.EngineLoop`를 다시 세운다.
   - 진행 중 요청은 원장 청구만 한다.
   - 끝난 요청은 `begin(executed=True)` = 청구 + 시도 기록이다.
   - 계획은 `loop.preview`, 정산은 `loop.settle`이다. 웹 CohortRunner·WP6 시뮬레이터와 같은 반복 억제 키·원장·정산이다.
   - AST 검사 테스트로 고정했다.
2. **근거 요건별 라우팅**:
   - 자기 보고 허용 기준 = 환자 질문
   - 진료 기록 필요 기준 = 문서 확인
   - 임상의 전용(원문에 구체 기준 없음) = 임상 검토
   - 수정 전 O는 의사 참고용(`physician_reference`) 임상 검토를 환자 질문으로 바꿨다.
3. **임상 검토가 제안되지 않던 결함**: 웹 `DEFAULT_BUDGET.clinician_minutes = 0`이고 임상 검토 정보원은 임상의 10분이다. 그래서 O에서 모든 CLINICIAN_REVIEW가 `over_budget`으로 빠졌다(NSCLC E3·E4·I2).
   - Follow-up 예산에만 임상의 시간을 넣었다.
   - 웹 실행기 예산·엔진 모드 기본값(legacy)은 바꾸지 않았다.
4. 문서 확인·임상의 판단 완료 상태는 만들지 않았다. 문서 권한이 없으면 쌍은 보류되고 CONFIRMED_ELIGIBLE이 나오지 않는다.
   원격에 새 문서 확인·임상의 검토 백엔드 브랜치는 없어 겹치는 변경은 없다.
