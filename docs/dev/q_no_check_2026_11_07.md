## 수정 2건

**F1. Follow-up 복원 세션이 운영 카탈로그에서 기준표를 잃음 (O, 결합에서만 드러남).**
`followup_api.default_catalog()`는 `parsed` 없이 trial_store 카탈로그를 넘긴다. 처음 Session은 `parse_criteria`로 기준표를
채우지만 `codec.restore_session`은 카탈로그의 `parsed`만 넣는다. 복원 세션은 기준표가 비고 `decision_state`가 그 시험을 건너뛰어
계획이 빈다. 결과: 담당자가 방금 받은 1순위 제안을 요청하면 **409 proposal_not_current**, Cohort C 대기열 항상 빔.
O의 테스트는 기준표를 넣은 합성 카탈로그만 써서 지나갔다. NSCLC뿐 아니라 기본 시험 세트에서도 같다.
수정: `codec._reload_parsed`가 평가된 시험의 기준표를 `trial_store.load`(사전 컴파일본, LLM 없음)로 다시 읽음.
회귀: `test_restored_session_keeps_trial_store_criteria` 외 5개가 수정 전 실패, 수정 후 통과.

**F2. 기본 Session 반복 질문 (N의 O-1 제안 적용).** `question_generator.screen`이 확보 계획에 남은 항목만 대상으로 둠.
보호 파일(pipeline.py, matcher.py) 변경 없음. `test_CD_failed_question_is_not_repeated` 2개 xfail -> 통과.
