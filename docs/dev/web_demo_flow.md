# 최종 웹 데모 경로 (2026-11-07, 동겸)

최종 데모는 **`/api/followup`(추가 정보 확인 흐름)** 하나로 보여 줍니다. 환자 화면의 기본 진행 방식이 "연구진 확인 요청"이고, 연구 담당자는 `/staff`를 씁니다.
기존 `/api/runs`는 환자 화면의 두 번째 선택지 "바로 분석"으로만 남깁니다(담당자 없는 단일 실행).

## 1. 두 경로의 차이

| | `/api/followup` (데모 기본) | `/api/runs` (바로 분석) |
|---|---|---|
| 역할 | 환자 + 연구 담당자 두 역할 | 환자 한 사람 |
| 추가 질문을 누가 고르나 | 담당자가 정책 엔진 제안(DCV 후보, C 순서)에서 골라 보냄 | AI가 실행 중에 바로 만들어 물음 |
| 진행 | 사례 단위, 요청·응답마다 재평가 (비동기, 며칠 걸려도 됨) | 한 번 실행 안에서 라운드 반복 (SSE 스트림) |
| 저장 | 사례·요청·응답·재평가 기록을 파일로 저장 (서버 재시작 뒤에도 유지) | 메모리 (최근 실행 몇 개만, 재시작하면 사라짐) |
| '모름'·연락 불가 | 같은 질문을 다시 하지 않고 서류 확인 등 대체 요청으로 연결 | 그 실행 안에서 보류 |
| 여러 환자 | 대기열이 열린 사례 전체를 한 코호트로 보고 확인 순서를 냄 (Cohort C) | 없음 |
| 권한 | 환자 = 사례별 HttpOnly 쿠키, 담당자 = `CTREC_STAFF_KEY` 헤더. 담당자는 환자 답변 입력 불가 | 실행별 쿠키 |
| 화면 | 환자: `/` (연구진 확인 요청), 담당자: `/staff` | `/` (바로 분석) |

결과 화면(추천 카드·상세·의사용 요약)은 두 경로가 같은 결과 형식이라 같은 렌더러(`app.js showResult`)를 씁니다.

## 2. 데모 시나리오 (필수 흐름 6단계)

오프라인 데모 서버: `CTREC_STAFF_KEY=<키> python scripts/followup_demo_server.py --port 8011` (실제 LLM·실제 환자·실제 시험 없음, 합성 시험 T-A/B/C)

1. **환자 초기 입력·후보 확인** - `/`에서 정보 입력, 시험 선택 → 초기 판정과 추천 카드
2. **담당자의 환자별 판정·부족 정보 확인** - `/staff`에서 담당자 키로 연결 → 사례 → 시험별 쌍 상태(7가지)·남은 확인·추천 표시
3. **담당자의 질문·문서 확인 요청** - 사례의 확인 제안에서 골라 보내거나, 대기열에서 바로 보냄
4. **환자 답변 또는 '모르겠어요'** - 환자 화면의 '연구진 요청' 칸 (20초마다 새 요청 확인, 새로고침해도 사례 유지)
5. **재평가 후 판정·추천·Inspector 갱신** - 환자 결과 화면이 다시 그려지고, 담당자 화면은 10초마다 갱신(요청 이력·재평가 기록), Inspector에서 라운드별 판정 변화
6. **여러 환자의 Cohort C 확인 우선순위** - 담당자 화면 '확인 대기열' 탭

## 3. 확정하지 않는 것

- 서류 확인 완료·의료진 판단 완료를 입력하는 백엔드 계약이 없음 → 담당자 화면에 완료 버튼이 없고 "입력 기능 없음(백엔드 계약 없음)"으로 표시. 해당 쌍은 "미확정 · 기록·서류 확인 전 / 의료진 판단 전"으로 표시.
- 담당자는 환자 답변을 입력할 수 없음: 화면에 경로가 없고, 서버도 담당자 헤더가 붙은 응답 요청을 403으로 거절.

## 4. 실제 브라우저 검증 (Chrome, 2026-11-07)

환자 3명 → 초기 판정 → 담당자 대기열(16건, 환자 3명 섞임)에서 요청 4건 + 사례 화면에서 2건 → 환자 1·3 답변, 환자 2 '모르겠어요' →
환자 2의 검사 수치 서류 확인 대체 요청 자동 생성("입력 기능 없음" 안내) → 담당자의 환자 답변 대리 입력 시도 403 → Inspector →
환자 1 추천 3건 → 1건으로 갱신. 콘솔 오류는 의도한 403 한 건뿐.

| 기능 | 상태 |
|---|---|
| 환자 입력·초기 판정, 요청 확인·답변·'모름', 재평가 뒤 결과 갱신 | 완료 (오프라인 대역) |
| 담당자 사례·판정·제안·요청·이력·재평가·Inspector, Cohort C 대기열과 대기열에서 요청 | 완료 (오프라인 대역) |

| 환자용 질문 문구 (지금은 기준 원문 영문) | 미완료 (`engine_runner._wording`, 질문 계약) |
