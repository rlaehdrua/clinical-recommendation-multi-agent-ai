# 웹 사용 안내 (임상시험 탐색 도우미)

입력한 환자 정보를 공개된 임상시험의 선정·제외 기준과 비교해, 검토해 볼 만한 임상시험과 근거를 정리하는 웹 화면입니다.

**임상시험 참여 자격을 확정하지 않습니다.** 실제 참여 가능 여부는 연구기관의 스크리닝과 연구자 판단으로 정해집니다.

## 1. 환자 정보 입력

입력 방식은 두 가지입니다.
- **직접 입력** (기본)
- **예시 사례 선택**: 챌린지 제공 및 합성 데이터이며, 실제 환자가 아닙니다.

직접 입력할 때 다음 정보가 있으면 도움이 됩니다.
- 나이, 성별
- 진단명, 병기
- 유전자·바이오마커 검사 결과
- 받은 치료와 반응
- 최근 검사 수치와 날짜
- 전신 상태(ECOG), 동반 질환, 복용 중인 약

**이름, 주민등록번호, 연락처, 주소, 병원 등록번호 같은 개인 식별 정보는 넣지 마세요.**

입력은 최대 20,000자입니다. "합성 예시 넣기"로 실제 환자가 아닌 예시 원문을 넣어 볼 수 있습니다.

"고급 설정"에서 비교할 임상시험을 고릅니다.
- 기본: 전체 시험에서 자동으로 추리기
- 직접 선택
- 후보가 모두 맞지 않으면 ClinicalTrials.gov 추가 검색 허용

환자를 고르거나 내용을 입력한 뒤 "분석 시작"을 누르면 바로 분석합니다. 분석 중에는 입력을 바꿀 수 없습니다.

## 2. 분석 진행

| 단계 | 바뀌는 시점 (서버 이벤트) |
|---|---|
| 분석 준비 | 실행 생성 |
| 환자 정보 분석 | 환자 정보 정리 시작·완료 |
| 임상시험 조건 검토 | 후보 추림, 기준 정리, 조건 비교 시작 |
| 추가 질문 | 질문 준비 도구 호출, 질문 생성, 질문 표시 (질문이 없으면 "해당 없음") |
| 답변 반영 및 재분석 | 답변 접수 뒤 다시 정리·비교 (답변이 없었으면 "해당 없음") |
| 추천 결과 정리 | 추천 정리 시작 |
| 완료 | 결과 수신 |

- 진행률 숫자는 표시하지 않습니다. 서버가 알려 준 단계만 보여 줍니다.
- 응답이 45초 넘게 없으면 기다리는 중이라는 안내가 나옵니다. 화면을 닫아도 분석은 서버에서 계속됩니다.
- **연결 끊김:** 브라우저가 자동으로 다시 연결합니다. 그래도 안 되면 화면이 실행 상태를 확인한 뒤, 마지막으로 받은 이벤트 다음부터 다시 받습니다. 같은 이벤트를 두 번 반영하지 않습니다.
- **새로고침:** 같은 탭이면 진행 상황과 결과를 다시 불러옵니다. 입력 원문은 보안상 브라우저에 저장하지 않으므로 다시 표시하지 않습니다.
- **탭을 닫았다 다시 연 경우:** 분석은 서버에서 계속됩니다. 같은 브라우저로 다시 접속하면 "진행 중인 분석 이어 보기" 버튼이 나옵니다. 누를 때만 이어 봅니다. 이미 끝난 분석은 다시 불러오지 않습니다. 같은 브라우저는 동시에 분석 1개만 할 수 있어, 새 분석을 시작하려 하면 이 버튼을 안내합니다.
- **기록 만료:** 끝난 분석은 2시간, 취소·오류로 끝난 분석은 2분 뒤 서버에서 지웁니다. 그 뒤 새로고침하면 "이전 분석에 접근할 수 없습니다"가 나오고 새 분석을 시작할 수 있습니다.
- **취소:** "분석 취소"로 멈춥니다. 이미 보낸 AI 호출 1건은 끝까지 진행된 뒤 멈춥니다.
- **종료 상태:** 완료, 취소됨, 시간 초과(기본 1시간), 오류가 화면에 구분되어 표시됩니다. 서버가 비용 상한(enforce)으로 운영되면 "비용 한도 도달", "사용량 확인 불가", "비용 관리 오류"도 따로 표시되며, 이때 결과 탭은 열리지 않습니다(완료·추천이 아님).
- **실제 AI 분석이 꺼진 서버(기본):** 화면 위에 "이 서버에서는 실제 AI 분석이 꺼져 있습니다"가 나오고, 분석을 시작해도 실행되지 않습니다. 입력한 환자 정보는 외부로 보내지 않습니다.

## 3. 추가 질문

질문은 기존 AI 질문 생성기가 만듭니다. 판단에 부족한 정보만 묻고, 질문 예산과 라운드 한도는 서버 정책을 따릅니다.

**답변 방식:**
- 질문 형식에 맞는 입력: 예/아니요, **하나 고르기·여러 개 고르기(객관식, Phase 9)**, 숫자(단위가 있으면 함께 표시), 날짜, 자유 입력
- 객관식: 선택지 문구가 그대로 답이 됩니다. 여러 개는 ", "로 이어 보내고, "기타"를 고르면 내용 입력란이 켜집니다("기타: 내용"). 선택지에 없는 답은 서버가 거절하며, 이때 질문은 그대로 남아 고쳐 보낼 수 있습니다.
- 형식 확인: 숫자는 숫자로 시작해야 하고(단위·부등호·범위 허용, 예: `1.2 mg/dL`, `<5`), 날짜는 달력에 있는 `YYYY-MM-DD`·`YYYY-MM`·`YYYY`여야 합니다. 형식이 틀리면 해당 질문에 오류가 표시되고 그 입력으로 포커스가 이동합니다. 의료적 범위(정상치 등)는 질문 정보에 없으므로 검사하지 않습니다.
- "모름"을 직접 적어도 "모름 · 확인 불가"와 같게 처리합니다.
- 모르거나 확인할 수 없으면 "모름 · 확인 불가"를 고릅니다. 빈칸도 "모름"으로 처리됩니다.
- "답변 확인"에서 보낼 내용을 확인하고, 필요하면 수정합니다. 보낸 뒤에는 바꿀 수 없습니다.
- 보내기에 실패하면 입력이 그대로 남으므로 "다시 보내기"를 누르면 됩니다.

답변 대기 시간(기본 30분)이 지나면 "모름"으로 처리하고 진행합니다.

## 4. 추천 결과

| 상태 | 뜻 |
|---|---|
| 공개 기준 충족 | 입력된 정보로 보면 공개된 기준을 모두 충족. 참여 확정이 아님 |
| 기록 확인 시 충족 가능 | 남은 조건이 답변상 충족이지만 진료 기록 확인 필요 |
| 의료진 검토 필요 | 원문에 구체 기준이 없어 의료진이 프로토콜과 대조해야 하는 조건이 남음 |
| 추가 정보 필요 | 아직 확인하지 못한 정보가 있음. 불충족이 아님 |
| 공개 기준 불충족 | 입력된 정보로 보면 맞지 않는 조건이 있음 |
| 평가 실패 | 오류로 판정하지 못함. 부적격이 아님 |

**시험별로 보여 주는 것:**
- 식별자, 제목, 모집 상태, 상태와 설명
- 조건 수: 충족, 불충족, 정보 부족, 추가 확인
- ClinicalTrials.gov 원문 링크 (https의 clinicaltrials.gov 주소만 링크로 만듦)

조건은 서버의 판정 함수로 나눈 묶음으로 보여 줍니다.
- 충족한 조건 / 충족하지 않은 조건
- 정보가 부족한 조건: 질문으로 확인할 항목
- 추가 확인 필요: 진료 기록으로 확인, 또는 의료진 확인
- 연구기관이 확인하는 절차 조건: 동의서 등, 판정에 영향 없음
- 분류할 수 없는 조건: 중립 안내

"조건별 판정과 근거 보기"에서는 조건마다 다음을 보여 줍니다.
- 선정·제외 기준 구분과 판정
- 판정 방식: 규칙 엔진, 또는 **AI 판정(검증된 사실 아님)**
- 근거 출처: 환자 기록, 답변(본인·보호자 보고), 출처 확인 불가
- 근거 인용
- 필요한 정보, 또는 진료 기록·의료진 확인이 필요한 이유

AI가 쓴 요약·설명·보고서에는 "검증된 사실 아님" 표시가 붙습니다. "새 분석 시작"으로 처음으로 돌아갑니다.

**내부 표기를 보이지 않게 하는 방식:**
- 서버가 만든 문구(제외 사유, 진료 기록·의료진 확인 메모, 추천 없음 사유)에는 `INELIGIBLE: 통과 3 / …` 같은 내부 표기가 섞일 수 있습니다.
- 화면은 이 문구를 고치지 않습니다. 같은 판정 정보(조건 분류, 모집 상태, 데모 여부)로 사용자용 설명을 따로 만들고, 원래 문구는 "시스템 원문 보기"로 접어 둡니다.
- AI 글에 내부 표기가 섞여 있으면 중립 안내를 보여 주고 원문을 접어 둡니다.
- 평가 오류는 오류 종류만 보여 줍니다.

## 5. 개인정보와 보안

- 환자 원문과 답변은 브라우저 저장소에 저장하지 않습니다. 탭 저장소(sessionStorage)에는 실행 ID만 둡니다.
- 환자 정보는 URL에 넣지 않습니다.
- 실행은 만든 브라우저만 볼 수 있습니다. 소유권 쿠키는 HttpOnly·SameSite=Strict입니다. 다른 브라우저에서는 실행 ID를 알아도 접근할 수 없습니다.
- 질문, 근거, 시험 제목 등 외부에서 온 글은 HTML로 해석하지 않고 글자로만 표시합니다. AI 보고서는 정화(DOMPurify)한 뒤 표시합니다.
- 오류 메시지에는 오류 종류만 표시하고, API 키나 환자 원문은 보여 주지 않습니다.
- 서버의 결과 파일 저장은 기본으로 꺼져 있습니다(`CTREC_WEB_SAVE_OUTPUTS`).
- 화면은 외부 CDN 없이 같은 서버의 파일만 씁니다. CSP로 인라인 스크립트·스타일과 외부 출처를 막습니다(`docs/web_security.md` 4절).

## 5-1. 접근성

- 키보드만으로 전체 흐름을 진행할 수 있습니다.
  - 본문 건너뛰기 링크가 있습니다.
  - 입력 확인을 누르면 분석 시작 버튼으로, 질문이 나오면 질문 제목으로, 결과가 나오면 결과 제목으로, 취소·시간 초과·오류 시에는 종료 사유로 포커스가 이동합니다.
- 상태 변화(분석 단계, 연결, 종료)는 화면 낭독기에 알립니다.
- 모든 입력·버튼에 접근 가능한 이름이 있습니다.
- 글자 대비는 WCAG AA 기준입니다(라이트·다크 모두 테스트로 확인).
- 320px 화면과 200% 확대에서도 가로 스크롤이 생기지 않습니다.

## 6. API 변경

**Phase 9:** `GET /api/ko`(시험 제목·질환·기준 한국어 번역, 공개 정보만)를 추가했습니다. 확인 질문 이벤트에 `options`·`unit`이 있습니다. 답변 제출은 객관식이면 선택지 안인지 검사합니다(아니면 400). 저장된 실행 다시 보기(`/api/replays`)는 보안 문제로 제공하지 않습니다(`docs/team_handoff.md` 4절).

**Phase 6-6:** `GET /api/runs/active`를 추가했습니다.
- 이 브라우저(클라이언트 쿠키)가 시작한 진행 중 실행의 ID만 돌려줍니다(`{"run_id": ... | null}`).
- 다른 브라우저에는 `null`입니다. ID를 알아도 실행별 소유권 쿠키 없이는 접근할 수 없습니다.

**Phase 6-1:**

`GET /api/runs/{id}/events?after=<마지막 이벤트 id>`를 추가했습니다.
- 화면이 직접 다시 연결할 때 쓰는 이어 받기 옵션입니다.
- `Last-Event-ID` 헤더가 있으면 헤더가 우선합니다(기존 동작).
- 소유권 확인은 기존과 같습니다.
